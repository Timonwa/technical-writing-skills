# Source material

Drop anything that already documents how a publication writes into this folder, and the writing guide is built from it instead of from an interview alone.

What belongs here:

- A style guide or writing guide, however informal — even a page of notes
- A brand voice or tone-of-voice document
- A terminology list, glossary, or list of words you avoid
- An editorial brief from a client or employer
- Contributor guidelines you publish for guest writers
- An exported set of published pieces, where the publication isn't reachable online

Any readable text format works. A PDF, a document export, a Notion page or a web page all work once the text is in a file here — a skill can read it, but it can't open your Notion account.

## How a skill uses it

**A source is not the writing guide**, and building one from the other is a conversion rather than a copy. A skill reads the source, maps whatever it settles onto `writing-guide.md`'s fields, and leaves the rest `unset`. The guide keeps its own shape and stays here; nothing rewrites it, and it remains the document a person argues with.

Three things follow:

- **Nothing is paraphrased.** Where a guide fixes exact wording — a sign-off, a banned phrase, a heading — it's transcribed verbatim, because the wording is the rule.
- **A guide that's silent leaves a gap.** Most guides say nothing about who a publication is _not_ for, or what an issue owes a subscriber. Those fields stay `unset` and get asked about, rather than inferred from the guide's tone.
- **A guide that contradicts the published work is reported, not resolved.** A skill says which pieces disagree with which clause and asks which wins. Guides drift ahead of practice, and practice drifts away from guides; only the author knows which one is currently right.

When the source changes, say so — the writing guide was built from a snapshot and needs rebuilding, since nothing links the two automatically.

Name files after the publication: `field-notes-style-guide.pdf`, `weekly-digest-voice.md`. A file named `guide.md` tells nobody which publication it governs.

## A note on other people's guides

A client's or employer's editorial guide belongs to them. Keep it here only for as long as you're writing for them, and don't publish it: keep the publication's folder in a private repository.
