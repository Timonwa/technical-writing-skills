# Plain language — vocabulary tiers, formatting, tone checks

## The four vocabulary tiers

Every word in a help centre falls into one of four tiers. Which words go in which tier is a product fact — ask for it; the tiers and the judgment are the standard. The examples below set the pattern — apply the same judgment to similar words.

1. **Prefer — plain everyday words.** The default register: money, balance, deposit, withdraw, cash out · account, sign up, log in · question, chance, likely.
2. **Use freely and gloss on first use — the product's own domain terms.** The vocabulary readers meet in the app and across the space (for a trading product: market, share, price, odds, order book, settlement). Use the real word — hiding it behind a vague substitute leaves readers unprepared — but explain it plainly the first time: "the order book — the live list of buy and sell offers for a market." Only swap in a plainer word when the domain term adds nothing ("your funds" → "your balance").
3. **Use only when required, and explain plainly the first time.** Terms that name something the reader must actually see, tap, or do (choosing a network for a deposit, connecting an account). Never assume they already know the term.
4. **Avoid unless genuinely unavoidable.** Behind-the-scenes plumbing the reader never touches (for a web3 product: seed phrase, gas, on-chain, non-custodial, smart contract) and all marketing language ("revolutionary", "democratizing", "empowering"). If a plumbing term genuinely comes up, describe what it does rather than leaning on the label.

The test separating tiers 3 and 4 is **teach-or-cut**: would a first-time user need this word to complete the task or understand the answer? Yes → tier 3. No → tier 4, cut it.

## Formatting

- **Numbered lists** for steps that happen in order; **bullets** for parallel options or a short set of points.
- **Bold** for button names, menu labels, and inline warnings only — not for emphasis everywhere.
- **Headings for scanning:** one title, H2 sections, H3 sub-steps. Don't stack everything as top-level headings.
- **Screenshots** when they help a reader find or confirm something in the app, with a short caption. No decorative images.
- **Show fee math and numbers where they aid transparency.** Readers trust what they can see — walk through a plain worked example first ("a 2% fee on a $50 trade is $1"), put any actual formula after the plain explanation and label it clearly, and never let the formula be the first thing a beginner hits. If the full math is long, summarize plainly and link the detailed page.

## Tone checks

- Read the first line alone. Does it answer the question? If not, rewrite it.
- Read it aloud. If you run out of breath, the sentence is too long.
- Would someone who has never used a product like this understand every word? If not, simplify or define.
